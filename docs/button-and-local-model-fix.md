## 实测性能

三张本地真实图片：公共麻婆豆腐照片、此前勺载相机屏幕翻拍红烧肉、公共非食物照片。屏幕翻拍不代表真实食物盘面测试。

| 样本 | 模拟器优化前总耗时 | 模拟器优化后总耗时 | iPhone优化后热启动 |
|---|---:|---:|---:|
| 麻婆豆腐3433×2281 | 8.49–8.57秒 | 0.98–1.01秒 | 0.50–0.51秒 |
| 勺载翻拍640×480 | 0.62–0.63秒 | 0.24秒 | 0.118–0.119秒 |
| 非食物5184×3456 | 18.29–18.42秒 | 1.54–1.55秒 | 0.77秒 |

iPhone首张冷启动约2.18秒（含模型加载）。上述为本机Debug测试，不是所有机型的性能承诺。原模型推理本身约30–43ms（模拟器CPU）；主要瓶颈是图片缩放。真机CPU/加速路径三张图的Top 3一致，最大候选分数差1.0133e-6。红烧肉翻拍样本的第一候选为红烧肉（约0.782）；这一个样本不能代表整体准确率。此次未重新训练模型，不声称准确率提高。分类器会把非食物强制归入已知菜类，因此继续要求用户确认候选；还需要独立的勺载/盘面样本与标注才能训练、标定拒识、报告准确率。

这里需要食物图像分类/检测；OCR适合包装文字，不能代替盘面菜品识别。模型在本地Core ML推理，不上传照片。Apple计算单元说明：https://developer.apple.com/documentation/coreml/mlcomputeunits

## 实体验收入口

常规路径：打开设备页 → 连接NOMI01 → 首页开始/继续本餐 → 开始记录 → 等“吃完离口后，短按餐勺记录这一口”。拍照/选菜不是按键入账的前置条件。

开发联调可显式传入 `-hardware-acceptance`：仅Debug，筛选NOMI01及已知广播服务，经正常GATT/hello验证后才开启本餐，显示“实体设备验收”横幅；不会模拟短按，Release没有该入口。该入口保持前台屏幕亮着，结束该模式后恢复系统自动锁屏。

```sh
xcrun devicectl device process launch --device <iPhone-UDID> \
  --terminate-existing com.kanglaide.zhiweishao -- -hardware-acceptance
```

准备好后短按两次并分别松开，核对两个不同事件ID、当日口数+2、缺少重量时待确认。约1.5秒长按松手休眠，再长按唤醒，核对没有额外口次。断线期间有效餐次短按应排队，重连回执后只补记一次。回放/模拟数据另用隔离模式。

可选真机UI测试`PhysicalButtonAcceptanceTests`需要显式环境`TEST_RUNNER_GRAMO_HARDWARE_ACCEPTANCE=1`。本机免费开发配置已有3个App，iOS拒绝安装额外的XCTest UI Runner；没有卸载用户其他App。模拟器UI测试及宿主内Core ML真机测试不受该限制。
